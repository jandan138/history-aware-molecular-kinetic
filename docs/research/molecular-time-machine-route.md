# Molecular Time Machine：一场碰撞，两个世界

## 给非技术读者的一句话

普通模拟器像一段已经拍好的录像：你可以倒回去看，但很难指着过去的某一
次碰撞说“把这里改一点，然后告诉我真正会发生什么”。Molecular Time
Machine 把每次碰撞都变成可点击的历史节点；改动一个节点后，它保留所有
确实没有受到影响的旧历史，只重新计算被这次改动触及的未来。

## 论文故事

### 第一幕：一帧画面不是一个未来

E1 的分子字母 `E` 先散开，再通过精确反演重新出现。另一个分支在登记的
可见统计上拥有同一个“现在”，却无法回到同一个未来。这说明决定未来的
不只是这一帧看得见的密度、温度和颜色，还有粒子之间隐藏的碰撞关联。

### 第二幕：滑杆不是历史

E2 原本希望找到一个特别的“碰撞分子预算”。结果是：允许的碰撞越多，
回声越强；但结构化预算并不比同剂量的随机对照更好。这个失败反而给出
了更清楚的转折：一个控制“保留多少”的滑杆，无法告诉创作者“究竟改哪
个原因”。

主文只需要一句桥：

> More collisions bring back more echo. But a slider cannot tell us which cause
> to edit. So we made every collision addressable.

### 第三幕：让过去可以被编辑

用户选择过去的第 2 次碰撞，只把两颗粒子的相对速度旋转 `1°`。位置不动，
总动量和能量不变。随后系统显示两条世界线：原世界恢复字母 `E`，编辑后
的世界沿真实硬球动力学走向另一种结果。

真正的算法贡献不是“两段不同视频”，而是系统知道哪些旧碰撞仍然有效：

```text
没有碰到改动的粒子 → 直接复用旧碰撞
碰到改动传播链的粒子 → 旧未来失效，进入重算
无法确定是否独立       → 扩大因果范围，绝不偷偷截断
```

因此黄色因果区域不是装饰图层；它就是重算范围本身。

## 为什么这比普通多分支模拟更具体

Many-Worlds Browsing 已经证明“浏览许多物理未来”是成熟的图形学方向；
Physics Storyboards 已经用关键时空结果帮助调节程序动画；Time Warp 也早
已建立离散事件回滚。我们的区别不能只是“有多个未来”或“能回滚”。

这里的编辑对象是一个有稳定地址的硬球碰撞，历史依赖由共享粒子自动
定义，并直接决定事件复用与精确重算。最终结果还要逐次碰撞与完整重算
一致。这是论文最应当守住的差异。

## 邓煜硬球工作的角色

邓煜、Hani、Ma 的工作告诉我们：从硬球动力学走向 Boltzmann 一粒子描述
时，碰撞相关并没有神秘消失，而是需要通过 cumulants 和 collision-history
molecules 被组织、传播和控制。它为“为什么应该看历史”提供科学动机。

但论文贡献来自图形学系统自己的闭环：

```text
隐藏碰撞关联（E1）
→ 简单预算无法定位原因（E2）
→ 可寻址碰撞时间线
→ 物理编辑
→ 精确因果重算与历史复用（E3）
→ 两个可验证的未来
```

我们不声称实现了证明中的 cutting algorithm，也不声称数学定理保证这套
有限粒子算法。

## 第一阶段结束时应当有什么

第一阶段不是一排防御性图表，而是一张主图、一段中性视频和一个可复现
证据包：

- 主图能看懂“选中一次碰撞 → 旋转 1° → 两个世界 → 因果范围”；
- 视频在同一镜头和同一时间轴下展示两条物理世界线；
- 证据包说明局部分支与完整重算一致，以及复用了多少旧历史；
- E2 的完整负结果留在补充材料，不占据论文高潮。

如果这一幕成立，后续再扩展到几何编辑、3D、原生并行和交互界面；如果
这一幕不成立，不用更多安全实验把故事拖长。

## 当前结果

冻结后的 E3 已返回 `go`：一次 `1°` 编辑让终局颜色分数从 `1.000000`
变为 `0.811782`，`33/128` 个粒子的位置出现可见变化；局部分支与完整重算
的 `106` 次碰撞配对全部一致，同时复用了 `79/105` 个旧碰撞事件，影响
范围峰值为 `33/128`。这意味着第一阶段的故事已经接上，而不是只剩下一
个工程设想。完整数值和哈希见
[E3 结果](../benchmarks/molecular-time-machine-e3-result.md)。
