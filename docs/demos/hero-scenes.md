# Hero Scenes — Molecular Echoes

The active SIG route uses three scenes with different responsibilities. None is a
variant of the old dynamic-LOD demo.

```text
Hero 1: Molecular Logo Echo       scientific hook
Hero 2: One Collision, Two Worlds algorithmic core
Hero 3: Choose the Cause          outcome-to-cause interaction
```

The old Zoomable Mixing, Correlation Labyrinth, and Expansion into Vacuum scene
specifications remain in the repository as deferred LOD assets, not active paper
evidence.

---

## Hero 1 — Molecular Logo Echo

### Scene

Passive-color particles begin as a bounded, clearly readable pattern:

- project initials;
- an hourglass;
- a butterfly-like symmetric symbol;
- or another simple shape robust to particle sampling.

The system evolves until the pattern appears mixed. At the pivot, create:

```text
exact reverse
chaotized reverse
DSMC reverse
history-budget branches
no-collision ghost
```

### Primary responsibility

Explain the scientific statement:

> same declared resolved present, different collision histories, different futures.

### Required evidence

- pivot `f1_h` and moment audit;
- exact/chaotized/DSMC current render under shared settings;
- passive-color recovery curve;
- anisotropy/echo curve;
- history-budget versus count-matched control;
- label distinguishing simulated reversal from reversed video.

### Strongest shot

Freeze the pivot with two branches side by side and an audit panel showing the
registered resolved state match. Resume forward time:

- exact reverse reconstructs the earlier pattern;
- chaotized and DSMC remain mixed;
- the budget slider controls partial recovery only when the mechanism gate passes.

### Avoid

- a complex logo requiring manual particle placement cleanup;
- claiming velocity reversal as novel;
- saying the exact microstates are the same;
- hiding pivot mismatch with blur;
- using a backward frame sequence as the result.

## Hero 2 — One Collision, Two Worlds

### Scene

A transparent periodic or bounded hard-sphere system has a selected collision in its
past. The user pauses, chooses the event, and applies a small registered edit:

- perturb one incoming velocity;
- rotate/modify the event under declared semantics;
- suppress the event in an extended-dynamics branch.

### Primary responsibility

Demonstrate that the collision causal graph is an algorithmic representation, not a
decorative overlay.

### Required views

```text
original future
local counterfactual branch
full-resimulation reference
collision causal graph / causal cone
```

### Required evidence

- selected event and fork time;
- affected particle/event fraction over time;
- local-vs-full state/event error;
- runtime and branch storage;
- fallback indication if the cone becomes global;
- immutable parent branch and branch lineage.

### Strongest shot

The difference begins at two particles, then spreads through a visible but
restrained causal cone. Original and counterfactual futures develop a clear passive-
color or escape/residence difference. A reference panel confirms that local branch
recomputation agrees with full resimulation.

### Avoid

- a fixed-radius influence region that silently misses dependencies;
- editing only the render, not the physical state;
- using graph motion as the only visible difference;
- choosing a perturbation so large that the branch trivially changes everything.

## Hero 3 — Choose the Cause, Direct the Future

### Scene

The recovered Molecular E is the outcome canvas. The user marks one visible feature
of the future—E4's fixed Hero uses the upper horizontal stroke. The system then:

- traces that feature's particles backward through the unedited collision DAG;
- ranks the few past collisions that cover the feature with least unrelated reach;
- exposes a small exact local-preview angle palette;
- saves one conservative edit as a second future.

### Primary responsibility

Show that the collision graph is not only an explanation of a branch after the fact:
it can turn a creator's desired consequence into an editable cause.

### Required interaction

```text
select a future feature
→ rank causal collisions in the past
→ browse exact branch previews
→ save one branch
→ verify that saved branch once against full resimulation
```

### Required evidence

- target membership and candidate-ranking manifest;
- explicit statement that ranking is baseline-only;
- exact-preview latency and cache keys;
- selected-feature change versus collateral foreground change;
- checkpoint, edit, causal-cone, and branch lineage;
- final local/full correctness for the saved branch only.

### Strongest shot

The user draws a box around one part of the recovered E. Three collision marks light
up on the past timeline. They choose the first recommendation and move a tiny angle
control; the selected stroke changes in the alternate future while most of the E
remains. A small inset reports that the saved branch agrees with full replay.

### Avoid

- turning the target choice into a hidden optimization over edited outcomes;
- showing a broad edit-type or density matrix instead of one authoring session;
- pretending cached previews are renderer effects rather than physical branches;
- requiring a geometry solver rewrite to explain the interaction.

## Optional supplementary scene — Same Present, User-Selected Future

At one pivot, expose a constrained surgery control:

```text
retain more original collision molecules
chaotize selected blocks
preserve specified moments/f1_h bins
```

The user chooses among repeatable alternate futures while the current resolved
appearance remains within tolerance.

This scene becomes primary only if the surgery control is stable and interpretable;
otherwise it remains a scientific supplementary result.

## Scene ownership of claims

| Claim family | Primary scene |
|---|---|
| same resolved present / history mechanism | Molecular Logo Echo |
| graph, replay, causal branch correctness | One Collision, Two Worlds |
| outcome-to-cause authoring and scoped interaction | Choose the Cause |
| geometry editing and broad native performance | deferred after E4 |
| correlation surgery authoring | Logo Echo or supplementary surgery scene |

## Shared visual constraints

All primary scene comparisons use:

- the same camera/time samples;
- matched particle display radius/density;
- stable passive-color mapping;
- identical trail and motion-blur policy;
- forward-rendered branch simulation after the fork;
- branch/run/metric/render manifests;
- neutral comparison before hero polish.

Shot IDs and timing are defined in [Storyboard](storyboard.md).
